SMC Fair Shift — 보안·개인정보 안내 (v0.82)

대상 병동 리더 · 배포 담당자 범위 브라우저 전용(Pyodide)판 · 로컬 웹앱(Flask)판

여러 병동에 이 프로그램을 배포하기 전에, 직원 이름·희망 근무(원티드) 같은 정보가 어디에 저장되고 어떻게 오가는지를 정리했습니다. 두 배포 형태 모두 결론은 같습니다 — 이 데이터는 외부 서버로 나가지 않습니다. v0.76~v0.82는 입력 오류 처리·배정 알고리즘 규칙·입력 화면 구성을 다듬은 버전들이라, 데이터 저장·전송 방식 자체는 바뀐 게 없어 이 문서의 내용은 v0.75 시점과 달라진 게 없습니다.

1가장 중요한 사실 — 서버가 없습니다(브라우저 전용판)

브라우저 전용판(Pyodide)은 Python 실행 환경 전체가 사용자의 브라우저 안에서 돌아갑니다. 입력한 병동인력표, 근무인력 기준, 신청(원티드), 생성된 근무표 — 이 모든 데이터가 그 폰·PC의 브라우저(로컬저장소, localStorage)에만 남고, 어떤 외부 서버로도 전송되지 않습니다.

여러 병동이 같은 링크로 접속해도 서로의 데이터를 볼 수 없습니다 — 애초에 각자의 브라우저 안에만 데이터가 있기 때문입니다. 로컬 웹앱(Flask)판은 이와 달리 병동 자체 컴퓨터 1대에서 서버가 돌아가는 구조이며, 데이터는 그 컴퓨터의 webapp/history/ 폴더에 저장됩니다 — 이 역시 인터넷 밖으로 나가지 않고, 그 컴퓨터를 쓰는 사람들끼리만 공유됩니다.

2배포 방식

대상받는 것비고
병동 리더 (편성 담당)앱 접속 링크(또는 로컬 실행 방법)근무표를 직접 만들고 수정하는 사람만 필요합니다
부서원 (일반 직원)완성된 근무표 엑셀 파일앱에 접속할 필요가 없습니다 — 링크를 부서 전체에 공유하지 않는 것을 권장합니다

편성 권한이 있는 사람(리더)에게만 링크를 주고, 나머지는 완성 결과물만 받는 구조로 운영하면 개인정보(직원 실명, 원티드 등)가 노출되는 범위 자체가 최소화됩니다.

3접속 통제 — 현재 상태

적용됨 브라우저 전용판은 첫 접속 시 비밀번호를 입력해야 화면이 보이는 게이트가 적용되어 있습니다. 링크를 몰라도, 링크를 알아도 비밀번호를 모르면 화면 자체가 열리지 않습니다.

다만 이건 서버 인증이 아니라 브라우저 안에서 해시값을 비교하는 방식이라 — "링크를 아는 사람이 우연히 또는 무심코 들어오는 것"을 막는 억제 수준입니다. 개발자도구를 다룰 줄 아는 사람이 작정하고 코드를 뜯어보면 우회할 수 있다는 점은 감안하고 사용하시면 됩니다. 비밀번호를 바꾸려면 pyodide-app/app.js 상단의 해시값을 교체하면 됩니다(브라우저 콘솔에서 새 비밀번호의 SHA-256 해시를 뽑아 넣는 방식 — 파일 안에 방법이 주석으로 적혀 있습니다).

로컬 웹앱(Flask)판은 애초에 병동 내부 컴퓨터에서만 접속 가능한 구조이며(그 컴퓨터 자체에 물리적으로 접근해야 쓸 수 있음) 별도의 비밀번호 게이트는 없습니다 — 컴퓨터 자체의 로그인 잠금이 그 역할을 합니다.

4파일(엑셀) 자체의 보안

내려받은 근무표 엑셀 파일에는 별도의 열기 암호를 걸지 않습니다. 대신:

  • 엑셀 파일을 전달할 때는 부서 공용 게시판보다 리더가 직접, 필요한 사람에게만 전달하는 것을 권장합니다
  • 파일과 접속 비밀번호는 같은 채널로 함께 보내지 않도록 합니다 — 예: 파일은 메일로, 비밀번호는 문자로 나누어 전달

5데이터 삭제·기기 분실 시

상황브라우저 전용판로컬 웹앱판
브라우저 데이터(캐시/사이트 데이터)를 지움그 기기의 근무표 이력·인원 정보가 즉시 삭제됩니다영향 없습니다(서버 컴퓨터에 저장)
다른 브라우저·다른 기기에서 접속이전 데이터가 보이지 않습니다(기기별 완전 분리)같은 서버에 접속하면 동일하게 보입니다
폰·PC 분실기기 자체 잠금이 최종 방어선입니다서버 컴퓨터 자체의 잠금·물리적 접근 통제가 최종 방어선입니다

이 특성 때문에 매달 최종 확정한 근무표 엑셀은 다운로드해서 별도로 보관해두는 것을 권장합니다 — 브라우저 전용판은 브라우저 데이터가 지워지면 앱 안의 이력을 복구할 방법이 없습니다.

6요약

서버 없음(브라우저 전용판) 또는 병동 내부 서버(로컬 웹앱판) → 외부 데이터 유출 경로 자체가 없습니다. 브라우저 전용판은 접속 비밀번호 게이트까지 적용되어 있습니다. 링크·비밀번호 공유 범위를 리더로 좁히고, 중요한 결과물(월간근무표·연간근무표)은 별도로 백업해두는 두 가지만 지키면 지금 구조로도 충분히 안전하게 운영할 수 있습니다.
